# The GOAT: decision log

Each entry records what was decided, who agreed and why. **Status:** Accepted unless marked otherwise. Dates are 2026-11-25 unless noted. "C" = Claude, "G" = ChatGPT, "P" = Peter.

| ID | Decision | Agreed | Rationale |
|---|---|---|---|
| D-01 | Launch as a **website first**; the iOS app comes later | P, C | Link sharing drives growth, there's no store review, and updates are instant. The app will wrap the same code later. |
| D-02 | Host on **GitHub Pages** at `eaglecoug2026/guess-the-goat`, with the backend on **Supabase** | P, C | Free, static and simple. Supabase gives Postgres, RLS and RPC with no server to run. |
| D-03 | **MVP scope** = the daily game plus real votes, integrity, sharing, analytics and content. **Battles and other modes deferred.** | C, G | Validate that people return before adding modes. Personal GOAT votes solve the cold-start data problem without Battles. |
| D-04 | **Every personal GOAT pick is a real vote.** One per player per category, updatable. | G, C | Real data from day one. Known anchoring bias is accepted and documented. |
| D-05 | **Blended ranking** `(votes + k·e)/(total + k)`, where `e` is a decimal estimate and `k = 100` (configurable) | C, G | A smooth move from estimates to real votes, with no overnight jumps. |
| D-06 | **Disclosure tiers:** 0 = Estimated, 1–499 = Blended, 500+ = Community with estimated weighting disclosed. The vote count is always shown. | G, C | At 150 votes, estimates are still about 40% of the blend, so honesty requires labeling. |
| D-07 | **Clues for the top 3 contenders** (4 each). If the blended #1 has no clues, the category is skipped that day and flagged `needs_clues`. | C, G | Keeps clues correct as rankings change, at a manageable content cost. |
| D-08 | **Frozen daily puzzles.** Same date = same puzzle number, answer, ranking and clues worldwide. Never edited after publishing. | C, G | Fairness, shareability and resistance to manipulation. |
| D-09 | **Local-midnight reset** (the Wordle model) | C, G | A natural daily routine for players. |
| D-10 | **Freeze at least 48 hours ahead**, with DST-safe date math, and refresh when a player returns after midnight | G, C | Buffer for the earliest time zones and for operations. |
| D-11 | **Offline:** use a cached official puzzle only. If it's not cached, offer a practice round and **never present a different puzzle as the daily**. | G, C | The official daily must be identical for everyone. |
| D-12 | **Outages don't break streaks.** Duplicate votes are prevented with idempotent upserts. | G, C | Players shouldn't be penalized for our failures. |
| D-13 | **Owner auth** = passphrase exchanged for a secure random 12-hour token: hashed in the database, kept in sessionStorage, revocable, with login rate limits | C, G | Proportionate for the MVP. No credentials are stored in the browser. |
| D-14 | **Vote integrity** = generous IP-hash rate limits, one vote row per player per category, frozen puzzles and monitoring. **Turnstile only if abuse appears.** | C, G | No friction for casual players. Shared IPs (schools, carriers) must not be blocked. |
| D-15 | **Pending suggestions are private.** The public sees approved categories only. | C, G | Prevents offensive public text. |
| D-16 | **Server-side vote counts** (trigger-maintained) | C, G | Downloading every vote row doesn't scale. |
| D-17 | Check the name "GOAT" against the existing sneaker brand **before the App Store**; not a web-launch blocker | C | Trademark risk for app naming. |
| D-18 | **Sharing is spoiler-free by default**, with an optional "include my pick". The share has the URL with an anonymous referral code, the puzzle number, and native share with clipboard fallback. | C, G | Growth loop without spoilers. The referral code contains no personal data. |
| D-19 | **First-party analytics only.** No cookies, no third-party trackers, events from an allowlist. SQL reports first, dashboard later. | C, G | Privacy-light, and retention can be measured with the anonymous ID. |
| D-20 | **Colorblind-safe indicators are P0.** Rank numbers and words always accompany colors. | G, C | Accessibility is a launch requirement. |
| D-21 | **Supabase Pro** is required before substantial promotion, not for the soft launch | G, C | Cost only when it's justified. |
| D-22 | **Rejected for now:** selling aggregated preference data; ads at launch | C, G | Privacy law, trust, and too little data to be worth it. To be revisited only with a privacy policy and scale. |
| D-23 | **Roles:** Claude owns code, database and deploys. ChatGPT owns content and independent review. Peter approves and merges. | P, C, G | Clear ownership. One repo is the source of truth. |
| D-24 | **Content format** = `content/categories.json` with 16 contenders, top 10 with whole-% estimates in descending order, and clues for the top 3. Must pass the validator script before import. | C, G | Repeatable content pipeline. |
| D-25 | **Rate limits key on the address Cloudflare sets** (`cf-connecting-ip`, else the last `x-forwarded-for` entry), not the first `x-forwarded-for` entry. Amends HANDOFF §6.4. | P, C | Verified live on 2026-11-25: the first entry is whatever the client sends, so rotating a fake header bypassed every limit, including owner login. Cloudflare rejects client-set `cf-connecting-ip`. Implemented in migration 0007. |
| D-26 | **Before launch day, the daily slot says when Daily GOAT #1 starts and offers practice rounds.** Applies while `config.launch_date` is unset or later than the local date. No streak or excused date is recorded. | P, C | The site went live early (O-4, 2026-11-25), before content and `launch_date` (O-2). Without this, every visitor would see the "can't load" notice. |
| D-27 | **Launched 2026-11-25, before the pre-launch gate (step 5).** `launch_date` = 2026-11-25; puzzles #1-#4 frozen the same day (action movie star, BBQ food, Best Picture winner, board game). The person fact-check, ChatGPT's review of Claude's clues and the iPhone test happen after launch. | P | Peter's call ("now, why wait"). Every clue passed the checker and Claude's first read. A clue error found later can be corrected for frozen puzzles with a correction note, and fixed in the catalog for future ones. |
| D-28 | **No clues, and no contender list up front.** The guess box shows nothing until 2 letters are typed, then up to 5 names with a word starting with them, picked by tap or arrows + Enter. Amends HANDOFF §3 (clues) and D-07 for the game screen. | P | Peter, 2026-11-25: showing every answer let people just tap names, and the clues gave it away. Clues stay in the catalog and snapshots, and the daily still needs a clued #1, so they can come back without a data change. |
| D-29 | **Site Stats feed.** The owner's Site Stats page on proctorpilot.com gets a The GOAT tab: new visitors, people who played, daily games finished and visitors in all, per Pacific day. `site_stats_daily` returns counts only (no player IDs, IP hashes or event detail) and needs a token held by the ProctorPilot server; this database keeps only its SHA-256 (`secrets.site_stats_token_sha256`). Migration 0008. | P | Peter, 2026-11-25, on the Site Stats page: "so add for myth/truth and also GOAT". The owner panel's today-only stats stay as they are. |
| D-30 | **Google Search Console.** The site is a URL-prefix property (https://eaglecoug2026.github.io/guess-the-goat/) in the Site Stats Google account, so the Site Stats page on proctorpilot.com can also show how people find The GOAT on Google. `index.html` carries Google's `google-site-verification` meta tag; it adds no tracking and sends nothing anywhere. Google re-checks it from time to time, so it stays. | P | Peter, 2026-11-25 (Pacific), about both game sites: "Yes, add them". |
| D-31 | **Hints on demand, give up, and the debate.** Clues come back as a Hint button (one at a time, up to 4). Give up ends the round as a loss. After the reveal, each category has a public board: a player types any GOAT (one of the 16 also counts as their vote), says why, and reads others' takes. One take per player per category. Links and blocked words are refused (list in `secrets.blocked_words`, not in the repo); the owner can hide takes and player deletion removes them. Each category starts with 3 starter takes written by us, labeled "Starter take". | P | Peter, 2026-11-27. Starter takes give an empty board something to react to; the label keeps them honest. |
| D-32 | **Broad groups, then categories.** Each category has `grp` (e.g. NFL) and `sub` (e.g. QB). More GOATs shows the groups, then the chosen group's categories; it replaces the 8 random with Shuffle. NFL now has 8 positions (5 new: TE, O-line, D-line, LB, DB). | P | Peter, 2026-11-27: "have NFL then sub QB WR DB Oline D Line, RB, etc." More groups and categories come next. |
| D-33 | **The debate shows 5 takes at a time, with Show more.** Your own take stays on top; "Showing N of total" under the list. Pages come from `take_page` (migration 0010), which starts each page after the last take shown, so it stays fast with any number of takes and nothing repeats or drops when new ones arrive. Amends D-31 (which loaded the newest 60 at once). | P | Peter, 2026-11-27: "don't show all comments … you are scrolling through a million comments." |
| D-34 | **A last name alone counts as that contender.** In the debate, one typed word that is the last name of exactly one contender (Jr., Sr., II, III, IV skipped) is stored as the full name and counts as the vote: "Jordan" -> Michael Jordan. The exact name still wins first, so one-word contenders are unchanged; a last name two contenders share (Tim Brown, Antonio Brown) stays a write-in. Matching is `match_pick` (migration 0011). Takes posted before this are not changed. Amends D-31. | P | Peter, 2026-11-27, after a player's "Jordan" landed as a write-in: "Yes, match last names". |
| D-35 | **Visit counts for Site Stats, and the owner left out.** `visit.js` sends one beacon per page opened to proctorpilot.com/api/visit.php (the owner's own server): page, referring site, share link or not, first visit and first that day. The server adds phone or computer and the approximate city and county from the IP (DB-IP City Lite + the Census places-by-county list, looked up on that server) and keeps daily totals only: no IP, no player ID, kept 2 years. The Site Stats tab shows them under the player counts. A "leave this device out" link (#leave-me-out=CODE, from the Site Stats page) stops that browser's beacons and puts its player ID on `site_stats_left_out`, which `site_stats_daily` now skips (migration 0012; only the code's SHA-256 is in `secrets`). privacy.html says so. Amends D-19 (first-party analytics only): the totals live on the owner's server, not a third party's. | P, C | Peter, 2026-11-27: "can we tell where users coming to our sites, are from what city county", "I dont want to see my own logins"; approved with "Build it". |
| D-36 | **Replies and editing on the debate board.** Under each take (starter takes too) players can Reply; replies are one level (no replies to replies), oldest first, folded under "N replies" and shown 5 at a time with Show more replies. A player can edit their own reply and their own take (Edit on the board); a changed one shows "edited". Replies follow the take rules: 2 to 280 characters, optional name, links and blocked words refused, 30 per hour per network, the owner can hide them (Latest replies in the owner panel), and deleting a player or a take deletes its replies. Migration 0013 (`take_replies`, `post_reply`, `edit_reply`, `reply_page`, `owner_replies`, `owner_hide_reply`). No new analytics events. | P | Peter, 2026-11-27: "I want the messaging section to be where you can reply and edit own message." |

| D-39 | **Crawlers aren't players.** Search engines, link scanners and web archives run the page like a browser, so they got a player ID and counted as new visitors: 19 of the first 33 (Google's crawler and its Search Console test, the Internet Archive, Palo Alto Networks link scanners, Amazon and Google datacenters, hosting companies). `track()` now stores nothing when the request's user agent names a crawler (the same markers as the stats server's crawler list on proctorpilot.com) and answers 0, so the game doesn't retry. The 19 already in the data are on `site_stats_crawlers`, each with the reason (the request log's network and browser name, or a frozen clock), and `site_stats_daily` skips them like the owner's left-out list; their events stay. Migration 0016. A scanner that uses an ordinary browser name still gets in until it's found and added to the list. Amends D-19 and D-29. | P, C | Peter, 2026-11-27, after the San Francisco "visitor" turned out to be the Internet Archive: "Yes, take them out". |
